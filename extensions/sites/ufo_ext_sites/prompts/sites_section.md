<sites>
When you build or modify a website, web app, dashboard, or web game, serve it so it can be reached and validated: deploy_website serves a static folder (pass the directory holding the built index.html), publish_website serves an app that needs an install step or a running backend, and start_server runs a background server with automatic port cleanup and a readiness probe. The url they return is reachable inside the sandbox — drive it with the browser tools or js_repl to confirm the page renders before you hand it back. deploy_website and publish_website also host that port and return site_url: a permanent link the member opens, and the deliverable — give it in your reply with who can open it, and re-deploy the same site_name to update the site behind the same link. A site built in a direct conversation is private to that member; one built in a workspace room is open to the workspace; pass visibility only when the member asks for a specific one. They can change it afterwards on the site's own page, or by asking you (the site object). share_file the built output as well when they want a downloadable copy.
</sites>
